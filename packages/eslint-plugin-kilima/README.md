# @kilima/eslint-plugin

The six CI-blocking lint rules of KP-ENG-11 §2.1. They turn the non-negotiables in `CLAUDE.md` into build failures. Where each rule applies is set in the root `eslint.config.js`.

| Rule                                                              | Applies to                                   | Catches                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| <a id="no-float-money"></a>`no-float-money`                       | all product code                             | Money-named identifiers and fields (amount, balance, stake, rake, pot, bet, fee, buyIn, prize, …) typed `number`, given number values (`100`, `parseFloat`, `Number()`, `Math.*`), or multiplied by fractional literals (`pot * 0.05`). Money is `bigint` minor units / `Money` (ADR-0005). Options: `extraWords`, `ignoreNames`.                              |
| <a id="no-math-random"></a>`no-math-random`                       | all product code except `tools/simbots`      | `Math.random`, including `Math["random"]` and `const { random } = Math`. Game randomness comes from the rng service (ADR-0010); ids use `node:crypto`.                                                                                                                                                                                                         |
| <a id="no-io-in-engine"></a>`no-io-in-engine`                     | `packages/engine-*` (not tests)              | Imports of Node built-ins (except `assert`) and I/O packages (pg, kysely, redis, kafka, fastify, pino, `@kilima/shared`, …); `setTimeout`/`setInterval`/`fetch`/`require`; `Date.now()`, `new Date()`; `process`, `performance`, `crypto`, `console`, `globalThis`. Type-only imports are allowed.                                                             |
| <a id="no-raw-ledger-entries"></a>`no-raw-ledger-entries`         | everything except `packages/ledger-postings` | SQL that writes `ledger.entries`, `ledger.transactions` or `ledger.balances`; Kysely `insertInto/updateTable/deleteFrom/mergeInto("ledger.…")`; building `LedgerEntry`, `LedgerEntryDraft`, `LedgerPosting`, `PostingLine` objects (`: LedgerEntry = {…}`, `as`, `satisfies`, `new`). Reads and DDL are allowed. Option: `entryTypes`.                         |
| <a id="no-hole-cards-in-logs"></a>`no-hole-cards-in-logs`         | all product code                             | Log calls (`log`, `logger`, `*Logger`, `req.log`, `console`, `.child()`) whose arguments contain fields or values named `hole`, `holes`, `holeCards`, `cards`, `deck`, `deckOrder`, `shuffledDeck` — in objects (any depth), spreads, template strings or `JSON.stringify`. The hand-record writer is exempted in the config when it exists. Option: `fields`. |
| <a id="no-direct-db-cross-schema"></a>`no-direct-db-cross-schema` | `services/*`                                 | SQL strings, `sql` templates and Kysely table arguments (`selectFrom`, joins, `withSchema`, …) that reference a schema owned by another service, per the KP-ENG-05 ownership map. `audit` is never queried directly. Option: `ownership`.                                                                                                                      |

The rules are syntactic (no type information) so they run fast on every file. They can miss cleverly hidden cases; code review and the database grants (KP-HBK-12) are the second line.

Tests: `pnpm --filter @kilima/eslint-plugin test` — every rule has passing and failing fixtures (`test/*.test.ts`).
