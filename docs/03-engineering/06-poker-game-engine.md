# 1. Purpose and Principles

This document defines the poker rules the platform enforces. It is **normative**: the production engine (`packages/engine-poker`, TypeScript) must behave exactly as described, and every example below is a machine-readable vector in `03-engineering/reference/test_vectors.json`, generated by the reference implementation `poker_reference.py`. CI fails if the engine and the reference disagree.

- **Pure and deterministic.** `apply(state, action) → { state, events } | error`. No I/O, no clock, no randomness inside the engine; the deck and timestamps are inputs. The same inputs always produce the same hand.
- **Server authority.** The engine runs only in `table-server`. Clients receive `legalActions` for display and pre-selection; only the server's acceptance counts.
- **Integer money.** All amounts are integers in minor units of the table currency. No floating point.
- **Game-agnostic boundary.** The engine implements the common `GameEngine` interface (section 12) used later by Bridge.
- The rules follow widely used online poker practice and the Poker Tournament Directors Association (TDA) rules where they apply online. The player-facing version is KP-LEG-07 (House Rules).

# 4. Dealing

- At hand start the table actor requests a shuffled deck from the `rng` service (KP-ENG-13). The response contains the ordered deck, a deck id and the commitment `SHA-256(deckId || cards || salt)`. The commitment is published in `hand:started`; the full deck and salt are revealed in the hand record after the hand, so any player can verify that the cards dealt match the commitment.
- Hole cards are dealt one at a time clockwise starting left of the button, as in live play; the board is taken from the deck in order after a burn card per street. (The order is fixed so that a certified deck maps to exactly one set of hands.)
- Hole cards are sent only to their owner. Board cards are sent to everyone when the street starts.
- Run it twice (cash only, optional per table): after an all-in with no further action possible and all involved players agreeing within 5 seconds, the remaining board is dealt twice from the same deck; each run awards half of each pot (odd unit to the first run).

# 5. Positions, Blinds and Antes

- **Button** moves one seat clockwise each hand. Kilima uses the **dead-button-free "moving button" rule online**: the button always moves to the next occupied seat; a player who misses the big blind must wait for it or post it to re-enter (cash).
- **Small blind** is the first occupied seat left of the button; **big blind** the next. **Heads-up:** the button posts the small blind, acts first pre-flop and last on later streets.
- New players in cash games may sit anywhere and either wait for the big blind or post a big blind to play immediately.
- **Straddle** (optional per table): the player left of the big blind may post 2× BB before cards; they act last pre-flop.
- **Antes:** tournaments use a **big-blind ante** (the big blind pays the ante for the whole table). The ante is dead money: it is not part of the big blind's street bet. Short Deck cash tables use antes for every player plus a button blind (configuration).
- A player who cannot cover a blind or ante posts what they have and is all-in.

# 6. Betting Rules

## 6.1 Order of action

Pre-flop: first seat left of the big blind (or of the straddle). Later streets: first active seat left of the button. Players who are all-in or folded are skipped.

## 6.2 Legal actions

The engine computes, for the player to act:

```
toCall   = min(currentBet − player.streetBet, player.stack)
fold     allowed when toCall > 0   (a fold when a check is possible is rejected with ILLEGAL_ACTION; the client offers "check")
check    allowed when toCall == 0
call     allowed when toCall > 0
bet/raise allowed when player.stack > toCall AND the action has been reopened to this player (6.4)
           AND at least one other player can still act
minTo    = currentBet + lastFullRaise        (a bet on an empty street: minTo = big blind)
maxTo    = NL: player.streetBet + player.stack
           PL: currentBet + (pot + toCall)    capped at the all-in amount
           where pot = all chips committed in the hand so far, including every bet on this street
An all-in for less than minTo is always allowed.
```

## 6.3 Minimum raise

The minimum raise increment is the size of the **last full bet or raise on this street** (at least one big blind). Example: blinds 50/100, open to 300 (increment 200), 3-bet to 900 (increment 600): the minimum 4-bet is to 1,500.

## 6.4 Incomplete all-in raises

An all-in that raises by **less than a full raise** does not reopen the betting for players who have already acted and are not facing at least a full raise when the action returns to them. They may only call or fold. If several short all-ins together amount to at least a full raise over the bet a player last acted on, betting is reopened for that player.

## 6.5 Pot-limit maximum

The maximum raise is to `currentBet + pot + toCall`. Example: PLO 50/100, first to act pre-flop: pot = 150, toCall = 100 → maximum raise to 100 + 150 + 100 = 350. After a raise to 350, the next player: pot = 500, toCall = 350 → maximum to 350 + 500 + 350 = 1,200; minimum to 600.

## 6.6 Betting-round vectors

@widths 2.9,1.1,1.6
| Situation | Structure | Expected |
|---|---|---|
| 6-max 50/100, first to act pre-flop | PL | raise min 200, max 350 |
| After a pot raise to 350, next player | PL | raise min 600, max 1,200 |
| Open 300, 3-bet 900, next player | NL | raise min 1,500, max all-in |
| Open 1,000; short all-in to 1,400; blinds fold; back to opener | NL | call 400, raise **not** allowed |
| Heads-up, button acts first pre-flop | NL | call 50, raise min 200 |
| Limp, small blind completes; big blind | NL | check or raise (min 200) |
| Tournament big-blind ante 100, blinds 50/100 | NL | pot 250 before action; min raise to 200 |

## 6.7 End of a betting round

The round ends when every player who is not folded or all-in has acted since the last full raise and has matched the current bet. If only one player remains, the hand ends and that player wins without showing. If all remaining players but one are all-in, the rest of the board is dealt without further betting ("run-out"), and all hands are exposed.

## 6.8 Timers and disconnection

@widths 2,3
| Rule | Default (configurable per format) |
|---|---|
| Action time | Cash 15 s (fast-fold 10 s), tournaments 15 s, AOF 8 s |
| Time bank | Cash: 30 s, +5 s every 50 hands to a 60 s maximum. Tournaments: 30 s at start, +10 s per level to 120 s |
| On timeout | Check if possible, otherwise fold. The player is marked **sitting out** after 2 consecutive timeouts in cash (folds in turn in tournaments) |
| Disconnection | No all-in protection. The action timer and time bank run as normal; the client reconnects to the same state (KP-ENG-04) |
| Sitting out | Cash: removed after 10 minutes or 3 missed big blinds; the stack returns to the wallet |

# 7. Showdown

- Order: the last player who bet or raised on the final street shows first; if there was no bet on the river, the first active player left of the button shows first; then clockwise.
- Players may muck a losing hand when shown down to; winning hands are always shown. All hands involved in an all-in are exposed automatically.
- "Show one card / show both" after winning uncontested is allowed (cash).
- All hole cards of every player, including mucked hands, are stored in the hand record and are visible to the integrity team; players see only cards that were shown.

# 8. Hand Evaluation

## 8.1 Hold'em and Short Deck

The best five-card hand from the player's two hole cards and the five board cards (any combination, including the board alone).

## 8.2 Omaha (4, 5 and 6 cards)

The best hand using **exactly two hole cards and exactly three board cards**. Examples (vectors):

@widths 1.6,1.6,1.1,1.8
| Hole | Board | Result | Why |
|---|---|---|---|
| `As Ad Ac 2h` | `Kd Ks 7h 8c 9d` | two pair (A-A-K-K-9) | only two hole cards: no full house |
| `Ah 2c 3d 4s` | `Kh Qh Jh Th 5c` | high card | Broadway would need four board cards |
| `Ah Ad 7c 8c 9s` | `Ts Jd 2h 3c 6c` | pair of aces | 7-8-9 would need three hole cards |
| `Kc Kd 4h 5h` | `Ks Kh 7c 2d 9s` | four kings | two from hand, two from board |

## 8.3 Hand categories

@widths 0.8,2.2,2
| Rank | Standard (Hold'em, Omaha) | Short Deck (Kilima default) |
|---|---|---|
| 1 (best) | Straight flush (royal flush = ace-high) | Straight flush |
| 2 | Four of a kind | Four of a kind |
| 3 | Full house | **Flush** |
| 4 | Flush | **Full house** |
| 5 | Straight | **Three of a kind** |
| 6 | Three of a kind | **Straight** |
| 7 | Two pair | Two pair |
| 8 | One pair | One pair |
| 9 | High card | High card |

- Ties inside a category are broken by the ranks of the category cards and then kickers, in the usual order. Suits never break ties.
- The ace plays high or low in a straight: `A-2-3-4-5` is the lowest straight in standard games; in Short Deck the lowest straight is **`A-6-7-8-9`**.
- **Short Deck rationale:** with 36 cards, flushes are rarer than full houses, and in seven-card hands straights occur more often than three of a kind (reference simulation: about 11.9 % vs 7.4 %). The table option `shortdeck.straightBeatsTrips = true` is available for pools that prefer the alternative ranking; the option is shown in the lobby and the table.
- **Evaluator self-check:** the reference enumerates all 2,598,960 five-card hands and matches the published frequencies (straight flush 40, four of a kind 624, full house 3,744, flush 5,108, straight 10,200, three of a kind 54,912, two pair 123,552, one pair 1,098,240, high card 1,302,540). For the 36-card deck it enumerates all 376,992 hands (flush 480 vs full house 1,728).

# 9. Pots, Side Pots and Distribution

## 9.1 Uncalled bets

At the end of the hand (or when everyone else folds), the part of the largest contribution that no other player matched is returned to its owner before pots are built. It is never raked.

## 9.2 Side pots

Pots are built in layers by contribution level of the players still in the hand. Chips of folded players stay in the layers they reached, but folded players cannot win. Adjacent layers with the same eligible players are merged.

@widths 2.2,2.8
| Contributions (seat: amount) | Pots |
|---|---|
| 1: 1,000 · 2: 3,000 · 3: 5,000 · 4: 5,000 (all in the hand) | main 4,000 (1–4) · side 6,000 (2–4) · side 4,000 (3–4) |
| 1: 200 · 2: 200 · 3: 1,500 | 1,300 returned to seat 3 · main 600 (1–3) |
| 1: 500 · 2: 2,000 · 3: 2,000 · 4: 800 (seat 4 folded) | main 2,000 (1–3) · side 3,300 (2–3) |

## 9.3 Awarding

- Each pot, starting with the last side pot, is awarded to the best eligible hand; ties split the pot equally.
- **Odd units:** when a pot does not divide evenly, remaining units are given one at a time to the tied winners in seat order starting from the **first seat left of the button**.
- Split boards with run it twice: each pot is split into run shares first, then each share is awarded independently.

# 10. Rake

Rake is the platform's fee in cash games. Tournament fees are separate (KP-ENG-07).

- **Percentage and cap** per stake, format and number of players dealt in are configuration (`rake_schedules`, KP-FIN-04). The engine receives `percentBp` (basis points, e.g. 500 = 5 %) and `cap` (minor units) at hand start; they cannot change during a hand.
- **No flop, no drop:** a hand that ends before the flop is dealt pays no rake.
- **Calculation:** `rake = min(floor(totalPots × percentBp / 10000), cap)`, computed after uncalled bets are returned.
- **Allocation to pots:** proportional to pot size (floor), remaining units assigned from the main pot onwards. This keeps side-pot players paying their fair share.
- Rake is posted in the same `hand_settlement` ledger transaction to the house rake account of the pool currency (KP-ENG-08). Rakeback and loyalty are computed from posted rake, never from client data.

# 11. Hand Record

- `ms` is the decision time in milliseconds (integrity analysis).
- Records are stored in ClickHouse (query) and in object storage with WORM retention (regulatory archive, KP-LEG-06).
- Players can download their own hand histories in a standard text format compatible with common tracking tools, subject to the third-party tools policy (KP-LEG-07).

# 12. Engine Interface

```
interface GameEngine<S, A, E> {
  family: "poker" | "bridge";
  create(config: TableConfig, seats: SeatState[], deck: Card[], now: Instant): { state: S, events: E[] };
  legalActions(state: S, seat: number): LegalActions;
  apply(state: S, seat: number, action: A, now: Instant): { state: S, events: E[] } | EngineError;
  timeout(state: S, seat: number, now: Instant): { state: S, events: E[] };
  isComplete(state: S): boolean;
  result(state: S): HandResult;           // pots, winners, rake, returned bets, stacks
  record(state: S): HandRecord;           // the immutable record of section 11
}
```

Poker events map one-to-one to the real-time events in KP-ENG-04 (`hand:started`, `hand:hole_cards`, `action:made`, `street:dealt`, `hand:showdown`, `hand:completed`). The table actor adds `seq`, timestamps, routing and persistence.

# 13. Acceptance Criteria

- All vectors in `test_vectors.json` pass in the TypeScript engine (CI job `engine-vectors`).
- The evaluator reproduces the 5-card frequency tables for the 52- and 36-card decks.
- Property-based tests (fast-check), 1,000,000 random hands per variant with random legal actions: chips are conserved (stacks + pots + rake + returned = starting stacks), no pot is awarded to a folded player, every card is dealt at most once, the hand always terminates.
- Differential test: 1,000,000 random showdowns evaluated by the production evaluator and by an independent open-source evaluator agree 100 %.
- Throughput: ≥ 50,000 actions per second per core for `nlhe` and ≥ 10,000 showdown evaluations per second per core for `plo6` (benchmark, CI informational; release gate at GA).
- The engine is part of the certified scope (KP-ENG-13 §7): any change to evaluation, dealing order, pots or rake requires a certification impact assessment.
